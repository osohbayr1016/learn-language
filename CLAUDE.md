# Nihongo — repo conventions

A free Japanese-learning platform for **Mongolian speakers**, on Cloudflare's
edge stack. Read this before writing code here; two agents work in this repo.

## Ownership

| Area | Owner |
| --- | --- |
| Learner product: kana, vocab, kanji, stories, SRS, PWA, `src/`, `worker/routes/{kana,kanji,vocab,srs,stories,audio}`, `shared/`, `scripts/etl` | Learner agent |
| Monetization: partner orgs, subscriptions, invoicing, entitlements, admin/partner API, `worker/routes/{partner,admin,billing}` | Monetization agent |

Both sides share `worker/index.ts`, `wrangler.jsonc`, and `migrations/`.
Coordinate before editing those three. Migrations are append-only — never
renumber or edit a migration that has been applied.

## Hard product rules

- **Learners never pay.** No paywall, no freemium gate, no ads in the learning
  flow. Revenue comes only from B2B training-center subscriptions.
- **No signup wall.** Anonymous-first: a learner studies immediately, progress
  lives in IndexedDB, and an account is an optional upgrade that merges local
  progress up.
- **Mongolian only.** Every user-visible string comes from `shared/i18n/mn.ts`.
  Never hard-code a user-facing string in a component — not even an error
  message, and not even "temporarily".

## Stack

Vite 8 + React 19 + TypeScript 7, Hono on Workers, D1 (SQLite), R2, Durable
Objects, deployed with Wrangler. Single package — not a workspace monorepo.

```
src/        React SPA (client only)
worker/     Hono API + Durable Objects (workerd only)
shared/     Types and data imported by BOTH — must stay runtime-agnostic
migrations/ D1 migrations, append-only
scripts/    Node-only build/ETL tooling
```

`shared/` is imported by the client, the Worker, and plain `node` ETL scripts.
It therefore must not touch `window`, Node builtins, or Cloudflare bindings.

## TypeScript rules that will bite you

TypeScript 7 is stricter than what you may be used to:

- **`baseUrl` is removed.** `paths` resolve relative to the tsconfig file.
- **Relative imports need the `.ts`/`.tsx` extension** (`./foo.ts`), because
  `rewriteRelativeImportExtensions` is on and plain `node` runs `shared/`
  directly via type-stripping.
- **Aliased imports must NOT have an extension** (`@shared/i18n`, not
  `@shared/i18n/index.ts`) — TS2877 otherwise.
- `erasableSyntaxOnly` is on: no `enum`, no parameter properties, no
  namespaces. Use `as const` objects and union types.
- `noUncheckedIndexedAccess` is on: indexing an array gives `T | undefined`.

Run `npx tsc -b` before considering anything done. Three projects are checked:
`tsconfig.app.json` (src + shared), `tsconfig.worker.json` (worker + shared),
`tsconfig.node.json` (scripts + vite config).

## i18n

```ts
import { t } from '@shared/i18n'
t('review.due', { count: 12 })   // params are type-checked against the message
```

A message with `{placeholders}` *requires* its params object. If you need to
accept a key as a prop, type it `SimpleMessageKey` (keys with no placeholders),
not `MessageKey` — otherwise `t()` will demand params it cannot know about.

## Cloudflare rules

- **Free tier is a design constraint, not a hope.** Every D1 query is a metered
  row read. Static content (kana, stroke data, level lists) is bundled or
  cached at the edge, never queried per request.
- Kana is deliberately served from the bundle (`shared/data/kana.ts`), not D1:
  ~150 fixed entries, zero row reads, works during a D1 outage.
- Durable Objects use **SQLite-backed classes** (`new_sqlite_classes` in the
  migrations block) — that is the variant on the free plan. Do not switch to
  `new_classes`.
- Per-user data: `Cache-Control: private, no-store` via `noStore(c)`.
  Static data: `cacheStatic(c)` plus an ETag.
- After editing `wrangler.jsonc`, re-run `npm run cf-typegen`.

## Data licensing

Upstream dictionary data (JMdict, KANJIDIC2, KanjiVG) is **CC BY-SA**. The
share-alike applies to the *data*, not to this repo's source code, but the
attribution must be displayed in-app. Never commit a derived data file without
recording its source and license in `ATTRIBUTION.md`.

No dictionary ships Mongolian glosses, so they are generated by a build-time
translation pass. Always keep the English source gloss and a
`translation_status` beside the Mongolian one so the pass is auditable and
re-runnable.

## Commands

```
npm run dev              # Vite + workerd, client and API together
npm run build            # tsc -b && vite build
npx tsc -b               # typecheck only
npm run cf-typegen       # regenerate worker-configuration.d.ts
npm run db:migrate:local # apply D1 migrations to the local dev database
```
